# SimpleEA v1.02.016b - Preset-Driven Voting EA (MT5)

**Code version:** 1.02.016b (`SimpleEA_v1-02-016b.mq5`, `#property version "102.016"`, revision tag `SEA_REV`)  
**Platform:** MetaTrader 5 (MQL5)

SimpleEA is a modular Expert Advisor designed to benchmark (and then improve on) MT5's classic Moving Average stop-and-reverse behavior by adding optional filters, a confluence voting layer, and exit management.

## Core execution flow

The EA runs once per new bar (new-bar gating in `OnTick()`), in this order:

1. Compute ATR (previous closed bar) for volatility and exit calculations.
2. Manage an existing position (breakeven and trailing) using the current ATR snapshot.
3. Build a signal direction via the Signal Engine:
   - apply global filters (time window, spread, minimum ATR)
   - determine bias (manual or auto)
   - apply optional HTF EMA slope veto
   - if `VoteThreshold > 1`, run voting and require minimum votes
4. Pass the final direction to the Trade Executor:
   - hold if already in that direction
   - optionally stop-and-reverse if enabled
   - open a new position with ATR-based SL/TP if configured


## Project structure

This EA is split into an orchestrator and two services:

- `SimpleEA_v1-02-016b.mq5` - inputs, preset mapping, orchestration, Strategy Tester report export.
- `SEA_SignalEngine.mqh` - indicator handles, filters, bias determination, voting.
- `SEA_TradeExecutor.mqh` - position lookup, stop-and-reverse, order placement, breakeven, trailing.

The main EA includes the services via:

- `#include <RRMS\SEA_TradeExecutor.mqh>`
- `#include <RRMS\SEA_SignalEngine.mqh>`

### File encoding note

The shipped `.mq5/.mqh/.json` sources are intended to be saved as **UTF-16 LE with BOM** (see the headers in the code). If you keep UTF-8 copies for review, ensure that the copies placed under `MQL5\Experts` and `MQL5\Include\RRMS` are UTF-16 LE with BOM so MetaEditor compiles them as expected.

## Execution model

- **New-bar execution only:** `OnTick()` runs signal generation once per new bar. Trade management (breakeven/trailing) is also updated once per bar.
- **Single-position model per symbol+magic:** the executor manages only one position for the current symbol and the configured magic number.
- **One ATR snapshot per bar:** ATR is read from the previous closed bar (`shift=1`) and reused for that bar's management and entry SL/TP calculations.

## Signal Decision Pipeline (Universal, applies to all presets)

SimpleEA evaluates trading decisions **once per new bar** (bar-close workflow). The exact same pipeline is used for all presets; presets simply override selected configuration values to enforce a coherent “strategy contract.”

### A) Hard veto filters (trade gating)
Hard filters are evaluated first. If any enabled filter fails, the Signal Engine returns **0** (no trade).

- **Time window** (if `UseTime=true`): entry allowed only between `StartHr` and `EndHr` (server time; window may wrap midnight).
- **Spread ceiling**: blocks entry when `spread_pips > MaxSpread`.
- **Minimum volatility (ATR)**: blocks entry when `atr_pips < MinATR`.
- **News blackout** (if `UseNews=true`): blocks *new entries* inside `[event−NewsPre, event+NewsPost]` for relevant events loaded from `calendar_statement.csv`.

### B) Bias (direction candidate)
If `BiasEnabled=false`, the EA produces a neutral direction (no new entries).

Otherwise, bias direction is determined by `BiasMode`:

- **AUTO**: direction is computed by the configured strategy:
  - **PRICE_CROSS**: price vs a single MA (benchmark-style).
  - **PAIR_CROSS**: MA-fast vs MA-slow (trend-style).
  - **SINGLE_SLOPE**: slope of a single MA (if used in your build).
- **MANUAL**:
  - `ManualSide=LONG` or `SHORT` forces direction.
  - `ManualSide=BOTH` removes the restriction and behaves like AUTO (direction still computed).

Note: in benchmark-style cross mode (`RequirePriceCross=true`), cross confirmation is computed using **closed bars** (shift=2 → shift=1) to avoid “price>MA state flipping” noise.

### C) HTF veto (optional)
If `UseHTF=true`, the EA computes a higher-timeframe direction (`HtfPeriod`, `P_HtfEma`) and allows a trade only when HTF direction matches the local bias direction.

### D) Voting (optional confluence)
Voting is enabled when `VoteThreshold > 1`. Only then do the enabled votes (`Use_*` flags) matter.

- If `VoteThreshold <= 1`: voting is **bypassed** and the system trades **bias-only**.
- If `VoteThreshold > 1`: the EA counts enabled “votes” (e.g., EMA recovery, ADX, MACD, RSI, Stoch, Bollinger, etc.).
  - Trade is allowed only when `votes >= VoteThreshold`.

### E) Execution policy (position reaction to signal flips)
Execution uses the **single-position per symbol+magic** model.

- If `CloseOnReverse=true`: a signal flip causes stop-and-reverse (close existing, open opposite).
- If `CloseOnReverse=false`: the EA holds the current position and ignores opposing signals (until exit/management closes it).

## Exits and Trade Management (SL/TP, Breakeven, Trailing)

All exit distances are volatility-scaled using **ATR from the previous closed bar** (one ATR snapshot per bar).

### 1) SL/TP placement (at entry)
At entry:

- **SL distance** = `ATR * SL_Mult` (if `SL_Mult = 0`, SL placement is disabled)
- **TP distance** = `ATR * TP_Mult` (if `TP_Mult = 0`, TP placement is disabled)

### 2) Breakeven (optional)
If `Use_BE=true`, breakeven uses ATR thresholds:

- **BUY**: when `Price >= Open + ATR * BE_Trig`, set `SL = Open + ATR * BE_Buff` if it improves SL.
- **SELL**: when `Price <= Open - ATR * BE_Trig`, set `SL = Open - ATR * BE_Buff` if it improves SL.

### 3) Trailing (optional)
Trailing is controlled by `TrailMode`:

- `TRAIL_NONE`: no trailing
- `TRAIL_ATR`: trail distance = `ATR * Trail_Mult`
- `TRAIL_FRACTAL`: trail to most recent confirmed swing fractal
- `TRAIL_PSAR`: trail to **PSAR(shift=1)** plus a cushion:
  - BUY: `SL = PSAR(1) − ATR(1) * PsarTrailCushionATR`
  - SELL: `SL = PSAR(1) + ATR(1) * PsarTrailCushionATR`

## Presets: What They Do and Why They Trigger Differently

Presets are applied inside `ApplySettings()` after inputs are read. They override selected fields to ensure a coherent configuration. This is why two presets can behave very differently even on the same chart.

### PRESET_CUSTOM (User controlled)
- Uses your inputs directly (no preset overrides).
- Recommended for manual research and controlled tuning.

### PRESET_MA_BENCHMARK (MT5 Moving Average compatibility)
Goal: replicate MT5 MovingAverage EA timing style and sizing behavior.

- Bias: benchmark confirmed **price/MA cross**
- Voting: bypass (`VoteThreshold=1`)
- Filters: off
- Exits: SL/TP off, BE off, trailing off
- Execution: stop-and-reverse on
- Uses benchmark MA inputs (period/shift) and benchmark-style sizing settings

### PRESET_TREND_REVERSAL (Baseline stop-and-reverse)
Goal: clean benchmark-like stop-and-reverse baseline.

- Bias: price/MA cross (confirmed)
- Voting: bypass (`VoteThreshold=1`)
- Filters: off
- Exits: SL/TP off, BE off, trailing off
- Execution: stop-and-reverse on

### PRESET_TREND_SCALP (Individual: intraday continuation with confluence)
Goal: more signals than swing, but still guarded by confluence + gates.

- Bias: trend-style (typically EMA1/EMA2 pair cross)
- Filters: News ON, HTF ON (time filter typically off unless desired)
- Voting: confluence bundle (e.g., EMA recovery + ADX + MACD) with higher threshold
- Exits: ATR SL/TP with BE + ATR trailing

### PRESET_TREND_SWING (Institutional: HTF + gating, fewer trades)
Goal: fewer, higher-quality trades with strong alignment.

- Bias: slower trend mapping (EMA3/EMA4 pair cross)
- Filters: News ON, Time ON, HTF ON, volatility/spread gates
- Voting: moderate threshold with trend confirmations
- Exits: wider ATR envelope + BE + trailing

### PRESET_RANGE_GRID (Consultant: conservative mean reversion)
Goal: risk-first mean-reversion regime; explainable and selective.

- Execution: no stop-and-reverse (avoid churn)
- Filters: News ON, Time ON, HTF ON (avoid trading into higher-timeframe trend)
- Voting: strict threshold, mean-reversion votes (RSI extreme + Stoch zone + Bollinger MR)
- Exits: symmetric ATR exits; trailing typically off

## How to Visualize Triggers (without guessing)

### 1) Experts log (authoritative audit)
On init, the EA prints:
- Program name + path (proves which binary is running)
- Preset (raw + name)
- VoteThreshold (input vs effective)
- Effective mapping (`AutoStrat`, `FastID`, `SlowID`)
- **OVERRIDES** list (which inputs were ignored due to preset enforcement)

If your live/test behavior does not match the selected preset, the init printout is the first place to verify reality.

### 2) CockpitPanel (recommended “decision-transparent” view)
For a human-auditable system, the CockpitPanel should show:

- **Preset + OVERRIDES** (what is actually active)
- **Veto status** (spread/ATR/time/news pass/fail + reason)
- **Bias result** (direction and which mapping was used)
- **HTF veto** (HTF direction + pass/fail)
- **Votes** (count and which enabled votes passed/failed)
- **Decision** (ENTER LONG/SHORT or NO TRADE)
- **Position snapshot** (side, lots, open, SL/TP, PnL)

This ensures you can visually confirm *why* a trade was taken (or blocked) on the exact bar it happened.

## Operational note: presets and “stale settings” in MT5 / Wine
MT5 applies input changes only on initialization. In Strategy Tester, use **Stop → Start** after changing inputs.

If you suspect stale binaries/settings (especially under Wine/macOS):
- rely on the **init stamp** (Program path + preset name + effective values + OVERRIDES).
If the stamp does not match what you intended, you are not running the build you think you are.

## Inputs overview

Inputs are grouped in the EA properties window.
For how these inputs are evaluated (filters → bias → HTF → votes → execution → exits), see Signal Decision Pipeline above.

### How to use presets (quick guide)

- **`InpPreset` is the master switch.** It determines which settings are *actually used* by the EA.
- **Use `PRESET_CUSTOM` when you want to tune parameters manually.** In this mode, the EA primarily uses the inputs in the `CUSTOM` groups (for example, `=== 5. CUSTOM: INDICATORS ===`).
- **Use any non-custom preset when you want a preconfigured behavior.** Presets set (and may force) key values internally in `ApplySettings()` to keep a coherent configuration. Inputs that contradict the preset may be **ignored**.
- **`PRESET_MA_BENCHMARK` (MT5 MovingAverage compatibility):** (requires `Inp_EnableMABenchmark=true`) the EA uses only the `=== 0c. BENCHMARK: MT5 MOVING AVERAGE ===` inputs for MA period/shift and MA-style sizing, and **ignores** the `CUSTOM` MA controls (group 5). The on-chart status panel and the Experts log explicitly show what is used vs ignored.
- **Applying changes:** MT5 inputs are applied only on initialization. After changing inputs, click **OK** (chart) or **Stop → Start** (Strategy Tester) to reinitialize the EA with the new values.


### Preset intent (personas)

Presets are implemented as deterministic *strategy contracts*. The labels below explain the design intent; they do not change behavior beyond the preset overrides:

- **Institutional-style** (risk-first trend following): `PRESET_TREND_SWING`
- **Experienced individual** (intraday continuation with confluence): `PRESET_TREND_SCALP`
- **Advisor/consultant** (conservative mean-reversion regime): `PRESET_RANGE_GRID`
- **Diagnostic / compatibility**: `PRESET_MA_BENCHMARK` (MT5 MovingAverage sync) and `PRESET_TREND_REVERSAL` (stop-and-reverse baseline)

In all non-custom presets, any input that conflicts with the preset may be ignored; the EA prints an **OVERRIDES** summary on init and (optionally) in the status panel.

### 0) Master preset

- `Inp_MagicNum` - unique magic number used to identify positions opened by this EA instance.
- `InpPreset` - one-click preset selection:
- `Inp_EnableMABenchmark` - safety switch: must be **true** for the EA to apply `PRESET_MA_BENCHMARK`. If false, the EA will force `PRESET_CUSTOM` even if the preset dropdown is on benchmark (prevents stale/loaded parameter sets from trapping you in benchmark mode).

  - `PRESET_CUSTOM`
  - `PRESET_MA_BENCHMARK` (MT5 MovingAverage compatibility / diagnostic sync)
  - `PRESET_TREND_REVERSAL` (stop-and-reverse baseline)
  - `PRESET_TREND_SCALP` (Individual: intraday continuation with confluence)
  - `PRESET_TREND_SWING` (Institutional: higher-timeframe aligned trend following)
  - `PRESET_RANGE_GRID` (Consultant: conservative mean reversion regime)

Presets override many settings in `ApplySettings()`. Bias configuration is still driven by the Bias settings below unless the preset explicitly forces a value (notably Trend Reversal).

### 1) Custom: logic and risk gates

- `Inp_CloseOnReverse` - if true, an opposing signal will close the current position before opening the new direction.
- `Inp_RiskPercent` - risk-based position sizing (percent of equity) when an SL is configured (i.e., `Inp_SL_Mult > 0`). Volume is calculated from SL distance using symbol tick size/value and normalized to broker min/max/step.
- `Inp_MaxSpreadPips` - spread veto.
- `Inp_MinATRPips` - minimum volatility veto (ATR in pips).

### 2) Custom: market bias

- `Inp_BiasMode` - `BIAS_AUTO` or `BIAS_MANUAL`.
- `Inp_EmaStrategy` - easy strategy mapping:
  - `EMA_STRAT_1_PRICE_CROSS` - price vs EMA1 (benchmark mode)
  - `EMA_STRAT_2_CROSS_1_2` - EMA1 vs EMA2
  - `EMA_STRAT_2_CROSS_3_4` - EMA3 vs EMA4
  - `EMA_STRAT_CUSTOM` - use the Advanced Bias inputs
- `Inp_BarShift` - vertical/bar shift:
  - `0` = evaluate the current forming bar
  - `1` = evaluate the last closed bar

### 2a) Advanced bias (used when `Inp_EmaStrategy = EMA_STRAT_CUSTOM`)

- `Inp_ManualSide` - `SIDE_LONG`, `SIDE_SHORT`, or `SIDE_BOTH`.
- `Inp_AutoStrat_Adv` - `STRAT_SINGLE_SLOPE`, `STRAT_PAIR_CROSS`, or `STRAT_PRICE_CROSS`.
- `Inp_BiasFast_Adv` and `Inp_BiasSlow_Adv` - which EMA slot(s) act as fast/slow.

### 3) Filters

- `Inp_UseTime`, `Inp_StartHour`, `Inp_EndHour` - hour-of-day trading window (server time). Overnight windows are supported.
- `Inp_UseHTF`, `Inp_HtfPeriod`, `Inp_HtfEmaPeriod` - Higher Timeframe EMA slope veto.
- `Inp_UseNews`, `Inp_NewsFile`, `Inp_NewsPre`, `Inp_NewsPost` - CSV news blackout: blocks *new entries* from `NewsPre` minutes before to `NewsPost` minutes after matching events for the symbol’s base/quote currencies (CSV columns: `Date,Event,Impact,Currency`).

### 4) Voting

- `Inp_VoteThreshold` - minimum number of votes required. If `<= 1`, voting is bypassed and the EA trades purely on bias (after filters and HTF veto).

### 5) Indicators

- `Inp_MaType` - `METHOD_EMA` or `METHOD_SMA` (applied to all EMA slots and the HTF filter).
- `Inp_MaHorzShift` - horizontal shift passed into `iMA()` handles (benchmarking support).
- Periods/modes for ADX, MACD, RSI, CCI, MFI, Stochastic, Bollinger Bands, and PSAR.

### 6) Active votes

Enable/disable each vote source:

`Inp_Use_EmaSig`, `Inp_Use_Adx`, `Inp_Use_Macd`, `Inp_Use_Rsi`, `Inp_Use_Cci`, `Inp_Use_Mfi`, `Inp_Use_Sto`, `Inp_Use_Bb`, `Inp_Use_Psar`, `Inp_Use_P123`, `Inp_Use_Ross`.

### 7) Exit and reporting

- `Inp_SL_Mult`, `Inp_TP_Mult` - ATR-based SL/TP multipliers (0 disables placement).
- `Inp_Use_BE`, `Inp_BE_Trig`, `Inp_BE_Buff` - ATR-based breakeven.
- `Inp_TrailMode`, `Inp_Trail_Mult` - trailing logic.
- `InpPsarStep`, `InpPsarMax`, `InpPsarTrailCushionATR` - PSAR parameters (vote + PSAR trailing).
- `Inp_ExportCSV` - export Strategy Tester report on shutdown.


## Presets (what they actually change)

Presets are applied inside `ApplySettings()` after loading your custom inputs.

Important behavior:

- Presets override many settings (vote threshold, enabled votes, exit options, and some filters).
- Unless a preset explicitly forces a bias strategy, the bias mapping still comes from your `Inp_EmaStrategy` / manual bias selection.

### PRESET_TREND_REVERSAL (Benchmark)

Designed to mimic a traditional moving-average stop-and-reverse system.

- `CloseOnReverse = true`
- Forces `AutoStrat = STRAT_PRICE_CROSS` using EMA1 as the reference (`BiasFastID = 0`)
- `VoteThreshold = 1` (bias-only)
- Filters off (time, news, HTF)
- SL/TP multipliers set to 0 (no broker-side SL/TP)
- Breakeven and trailing disabled

### PRESET_TREND_SCALP (Sniper)

Higher-confluence trend continuation setup.

- `CloseOnReverse = true`
- `VoteThreshold = 3`
- Enabled votes: EMA recovery, ADX, MACD
- `SL_Mult = 1.5`, `TP_Mult = 3.0`
- Breakeven enabled
- `TrailMode = TRAIL_ATR`

This preset also enables News and HTF veto by default.

Note: this preset does not force a bias strategy; it uses whatever bias configuration you have selected (unless you change it).

### PRESET_TREND_SWING (Institutional)

Institutional-style trend following: fewer trades, stronger gating, and a higher emphasis on alignment.

- `CloseOnReverse = true`
- `VoteThreshold = 2`
- Forces bias to EMA3/EMA4 pair cross
- Enables News, Time window, and HTF veto
- Enabled votes: EMA recovery, ADX, MACD
- `SL_Mult = 2.0`, `TP_Mult = 4.0`
- Breakeven enabled
- `TrailMode = TRAIL_ATR`

### PRESET_RANGE_GRID (Conservative)

Conservative range/mean-reversion configuration (despite the legacy preset name).

- `CloseOnReverse = false`
- `VoteThreshold = 4`
- Enables time filter, news hook, and HTF filter
- Enables votes: RSI (forced to `RSI_FILTER_EXTREME`), Stochastic, Bollinger (forced to `BB_MEAN_REVERSION`)
- `SL_Mult = 2.0`, `TP_Mult = 2.0`
- Trailing disabled

## Benchmark sync guide (MT5 "Moving Average" EA)

The dual-shift implementation is specifically intended to let you replicate the timing style of MT5's built-in Moving Average EA, and then add filters/exits.

A typical "sync" configuration is:

- `Inp_MaType = METHOD_SMA`
- `Inp_EmaStrategy = EMA_STRAT_1_PRICE_CROSS`
- `Inp_BarShift = 0` (aggressive: current bar) or `1` (confirmed: previous closed bar)
- `Inp_MaHorzShift` = match the MA indicator shift you want to benchmark
- `Inp_CloseOnReverse = true`
- `Inp_VoteThreshold = 1`
- `Inp_SL_Mult = 0`, `Inp_TP_Mult = 0`

Then enable improvements one at a time, for example:

- Raise `Inp_VoteThreshold` and enable one vote (ADX or MACD) to reduce noise.
- Enable HTF veto to avoid trading against higher-timeframe slope.
- Use `TRAIL_ATR` to hold winners longer than stop-and-reverse.

## Strategy Tester CSV report

If `Inp_ExportCSV = true`, the EA writes a CSV report on shutdown when running in the Strategy Tester (`MQL_TESTER` must be true).

Report contents:

- Test configuration (preset, EMA strategy, vote threshold)
- Key statistics (net profit, profit factor, expected payoff, Sharpe, recovery factor)
- Drawdown metrics
- Deal history (time, type, volume, price, profit, running balance)

The report is created with a name like:

`Report_SimpleEA_<SYMBOL>_<PERIOD>_<STARTDATE>_<ENDDATE>.csv`

## Operational notes and current limitations (v1.02.016)

These points matter for live behavior, backtest interpretation, and multi-instrument portability:

- **Trailing modes:** `TRAIL_ATR`, `TRAIL_FRACTAL`, and `TRAIL_PSAR` are implemented.
  - `TRAIL_PSAR` uses the last confirmed PSAR value (shift=1) plus an optional cushion: `InpPsarTrailCushionATR * ATR`.

Additional behavior notes (relevant for configuration and expectations):

- **Risk sizing requires an SL price:** risk-based volume requires a configured stop (`Inp_SL_Mult > 0`). If SL is disabled or symbol tick properties are unavailable, the executor falls back to the symbol’s minimum volume.
- **Instrument coverage (FX + metals):** lot sizing is based on `SYMBOL_TRADE_TICK_SIZE` and `SYMBOL_TRADE_TICK_VALUE_LOSS` (fallback: `SYMBOL_TRADE_TICK_VALUE`), so it is designed to work for 5-digit FX, JPY pairs, and XAU/XAG CFDs. Correctness depends on broker-provided symbol properties.
- **News filter scope:** the news blackout blocks *entries only*; it does not force-close existing positions. Impact handling is conservative: explicit “Low” events are ignored; anything else is treated as relevant.
- **ATR period is fixed at 14** in the signal engine (`iATR(..., 14)`), and ATR is read from the previous closed bar (`shift=1`).
- **Spread/ATR thresholds are pip-normalized:** `MaxSpreadPips` and `MinATRPips` are interpreted using a pip-size heuristic (digits 5/3 => 1 pip = 10 points; digits 4/2 => 1 pip = 1 point). This covers typical FX majors, JPY pairs, and common metals CFDs, but broker symbol conventions can vary.
- **Time filter uses broker server time** (`TimeCurrent()` hour), not local time.
